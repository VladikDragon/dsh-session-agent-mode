# dsh-session-agent-mode

[![release](https://img.shields.io/github/v/release/VladikDragon/dsh-session-agent-mode?label=release)](https://github.com/VladikDragon/dsh-session-agent-mode/releases)
[![license](https://img.shields.io/github/license/VladikDragon/dsh-session-agent-mode)](LICENSE)

Компактная метка режима (agent preset) на строке сессии в боковой панели DeepSeek
Harness — только для сессий, которые работают не в штатном режиме.

> *English summary: a DeepSeek Harness web plugin that shows which agent preset each
> sidebar Session runs as a compact chip right after the update time, and shows nothing
> at all for Sessions on the everyday preset.*

## Что делает

У строки сессии появляется маленькая метка сразу после времени обновления — но только
если сессия работает не в штатном режиме:

| режим | метка |
| --- | --- |
| `ptc` | **PTC** — пакетные вызовы инструментов и фильтрация их результатов |
| `minimal` | **Минимум** — терминал и чтение картинок, самый маленький набор инструментов |
| `cordis` | **Автор** — сборка плагинов и режимов DSH через разговор |
| свой режим | имя, которое публикует Хост для этого пресета |

Сессии на штатном пресете не показывают ничего, поэтому обычный список выглядит ровно
так же, как до установки плагина. Наведение курсора показывает подсказку с описанием
пресета.

## Можно ли переключить режим у сессии?

Только пока она пустая — до первого сообщения. В композере у новой сессии есть выбор
пресета, и Хост разрешает переключение до старта первого хода. После первого хода режим
зафиксирован: Хост отвечает `agent-preset/locked` («This session has already started»).
Чтобы работать в другом режиме, начните новую сессию с нужным пресетом или смените
пресет по умолчанию в настройках — тогда будущие сессии будут создаваться с ним.

## Установка

Плагин ставится в профиль как обычный пакет:

```
dsh plugin --profile desktop add github:VladikDragon/dsh-session-agent-mode
```

После установки добавьте его в `dsh.profile.bundles` профиля — через менеджер плагинов
или вручную в `~/.dsh/profiles/<профиль>/package.json`:

```json
"dsh": {
  "profile": {
    "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-session-agent-mode"]
  }
}
```

Локальная разработка — из клона:

```
git clone https://github.com/VladikDragon/dsh-session-agent-mode
dsh plugin --profile desktop add file:C:/path/to/dsh-session-agent-mode
```

Перезапуск приложения нужен только при добавлении нового **пакета**. Правки уже
подключённого плагина подхватываются выключением и включением его строки в менеджере
плагинов.

## Как это работает

```
package.json          манифест: dsh.bundle.patch + dsh.client (platform web)
cordis.patch.yml      одна строка Loader с id session-agent-mode
index.js              host-половина: пустой apply(), нужен только чтобы у плагина
                      была строка на стороне хоста
client.js             браузерный бандл: метка режима в строке сессии
test/client.test.cjs  сценарии на макетах сервисов и загрузчика модулей
```

Клиентская половина объявляется в `package.json` и зависит от двух пакетов:

```json
"dsh": {
  "client": {
    "platform": "web",
    "immediately": true,
    "inject": [
      "@deepseek-ai/dsh-client-ui-session",
      "@deepseek-ai/dsh-client-ui-workspace"
    ]
  }
}
```

`ui-session` объявляет сервис `uiSession`, `ui-workspace` — слот строки сессии, в
котором плагин занимает место `sidebar.session.row.trailing`. `inject` обязателен: без
него регистрация пришлась бы на сервисы и слоты, которых ещё нет.

### Метка

Метка — ячейка `agent-mode` (`order: 20`) в штатном слоте `sidebar.session.row.trailing`.
Она читает `projectionValues.agentPreset` из уже загруженного списка сессий: лишних
запросов нет, сессию она не удерживает и не открывает.

Для штатного пресета (`standard`) и для сессии, у которой пресет не указан, компонент
возвращает `null` — строки это не касается вообще.

Имена и описания пресетов приходят из одного чтения `remote.agentPresets.list()`.
Встроенные режимы (`standard`, `ptc`, `minimal`, `cordis`) подписаны собственными
короткими словами плагина, поэтому метка работает и до ответа Хоста, и без него.
Ростер запрашивается один раз на старте и ещё раз — только когда в списке появился
идентификатор пресета, о котором плагин ещё не спрашивал. Ответ без этого
идентификатора повторного запроса не вызывает: иначе каждое изменение списка сессий
стоило бы одного запроса к Хосту. Неудачное чтение забывает запрошенные идентификаторы,
поэтому следующее изменение списка повторит попытку.

### Локаль

Словари лежат прямо в `client.js` и регистрируются в namespace `sessionAgentMode`:

```js
ctx.locale.register('sessionAgentMode', DICTIONARIES)
```

Ключи — `preset.standard`, `preset.ptc`, `preset.minimal`, `preset.cordis` и `hint`;
языки — `ru`, `en`, `zh`.

Кодировка: каждая не-ASCII строка в `client.js` записана как `\uXXXX`, поэтому бандл
остаётся чистым ASCII. Кириллица, отданная в бандле как есть, декодировалась с чужой
кодовой страницей и рисовалась на странице мусором.

## Ограничения

- Только веб-клиент (`platform: "web"`); в TUI метки нет.
- Метка опирается на поле `projectionValues.agentPreset` в списке сессий. Это не
  публичный контракт: если DSH переименует поле, метки перестанут появляться, но
  страница не сломается.
- Свой режим подписывается именем из ростера Хоста; пока ростер не ответил, метка
  показывает идентификатор пресета как есть.
- Переключить режим у уже начатой сессии нельзя — это ограничение Хоста, а не плагина.

## Разработка

Сборки нет: `client.js` — обычный скрипт, который загружается загрузчиком модулей хоста
и получает `react` через `require`. Правки применяются перезапуском приложения;
проверить синтаксис можно `node --check client.js`.

Тесты идут без браузера и без DSH: `test/client.test.cjs` подменяет загрузчик модулей,
`sessions`, `remote.agentPresets` и слоты макетами и прогоняет 17 сценариев — регистрацию
ячейки, ASCII-чистоту бандла, словари, штатный пресет, встроенные и свои режимы,
подсказку, число чтений ростера, повтор после ошибки и снятие подписок.

```
npm test
```
